Visão Geral do Projeto

Bem-vindo à documentação oficial do Vagas e Oportunidades. Este projeto foi concebido para atuar como um ecossistema completo e automatizado de extração, análise e notificação de vagas de emprego.

Status: Produção ativa. O sistema realiza scrapings horários e possui interface consumidora em React (Vite).

Objetivos de Negócio

  • Garantir ao candidato acesso rápido a oportunidades sem depender exclusivamente das notificações falhas das redes profissionais.
  • Filtrar vagas de altíssima concorrência.
  • Prover uma análise de aderência (Match Score) usando Inteligência Artificial (NLP).

Tecnologias Principais

Camada Tecnologia Propósito
Frontend React (Vite) na Vercel Interface de usuário responsiva e moderna, hospedada gratuitamente na Vercel.
Backend Python (Flask) no Render API RESTful, motor TF-IDF e rotinas de scraper rodando continuamente em nuvem.
Banco de Dados PostgreSQL (Supabase) Banco de dados escalável e persistente na nuvem para garantir a integridade total dos assinantes e usuários. (Fallback local via SQLite)
Automação APScheduler Agendamento de extrações e disparos de e-mail automatizados.

Arquitetura do Sistema

O fluxo de dados da aplicação é desenhado para ser resiliente e assíncrono. O Frontend React atua apenas como consumidor dos dados que o Backend gera de forma autônoma.

Diagrama Lógico

[LinkedIn API/Scraper] ----(Extrai a cada 1h)---> [ JSON Local (.tmp) ]
                                                        |
[Currículo PDF] ---(PyMuPDF / OCR)--> [TF-IDF Match] ---+---> [ Frontend React ]
                                                        |
[Newsletter Jobs] <-------(Cron Múltiplo)---------------+

 │    └── /.tmp                 (Vagas em JSON / CVs Salvos)
📄 Docs / Getting Started / Instalação & Setup

Instalação & Setup Local

Siga os passos abaixo para rodar o projeto em sua máquina local para desenvolvimento.

1. Backend (Python)

Recomendamos o uso de um ambiente virtual (venv).

cd execution
python3 -m venv venv
source venv/bin/activate
pip install flask pyjwt linkedin-api apscheduler pymupdf scikit-learn pdf2image pytesseract
python server.py

O servidor iniciará na porta 5001.

2. Frontend (React)

npm install
npm run dev

O Vite subirá na porta 5173, e os proxies no vite.config.js farão o roteamento das chamadas /api/* para a porta 5001 do Python.

📄 Docs / Core Engine / Scraper (LinkedIn)

Motor de Scraper

O linkedin_scraper.py é o coração da aquisição de dados. Ele utiliza a biblioteca não-oficial linkedin-api para buscar oportunidades.

Estratégia de Dupla Fonte

O script varre duas fontes simultaneamente para cada termo-chave:

  1. Seção de Vagas: Busca as oportunidades formais postadas por empresas.
  2. Feed / Timeline: Busca posts de recrutadores. O frontend consolida essas buscas se o titulo_vaga for "Vaga via Post" garantindo o termo_busca correspondente.

Regras de Ordenação

As vagas extraídas são ordenadas pela concorrência antes de serem salvas:

vagas_encontradas.sort(key=lambda x: (
    x["concorrencia"]["comentarios"], 
    x["concorrencia"]["compartilhamentos"]
))

Isso garante que o painel exiba primeiro oportunidades menos saturadas.

📄 Docs / Core Engine / Match de Currículo

Sistema de Matching (TF-IDF)

Para fornecer o "Score de Afinidade" aos candidatos, implementamos uma análise vetorial via Scikit-Learn no arquivo server.py (rota /api/analyze).

Fluxo de Leitura

1. O usuário anexa um PDF.

2. O PyMuPDF (fitz) tenta ler o texto puro.

3. Se a extração resultar em menos de 50 caracteres (indicando um PDF de imagem), o sistema invoca o pytesseract (OCR) para forçar a extração ótica.

Cálculo TF-IDF

vectorizer = TfidfVectorizer(stop_words=stopwords_pt)
tfidf_matrix = vectorizer.fit_transform([texto_curriculo, texto_vaga])
similaridade = cosine_similarity(tfidf_matrix[0:1], tfidf_matrix[1:2])
score = round(similaridade[0][0] * 100)

Se o score for maior que 85%, o sistema o classifica na interface com cores de destaque.

📄 Docs / Core Engine / Newsletter System

Disparo de Newsletters

A funcionalidade de e-mails é controlada pela tabela subscribers no banco de dados newsletter.db e roda via APScheduler em background.

Frequências de Disparo

  • 1x ao dia: E-mail consolidado matinal (09:00).
  • 3x ao dia: Manhã, Tarde e Noite (09:00, 14:00, 19:00).
  • 5x ao dia: Horário comercial intenso (08:00, 11:00, 14:00, 17:00, 20:00).

Lógica de Caching e Disparo (Fallback)

Para garantir que o usuário sempre receba a newsletter programada, o sistema usa uma técnica de fallback:

  1. Tenta carregar o cache vivo .tmp/vagas_extraidas.json gerado pelo robô.
  2. Se não encontrar ou o arquivo estiver vazio, automaticamente consome o banco de dados tático embarcado no frontend (vagasData.json).

SMTP e Integração

O envio usa a biblioteca padrão smtplib via protocolo STARTTLS (Porta 587). No ambiente de produção, é projetado para operar com contas SMTP transacionais de alta confiança (como SendPulse, Brevo, ou Resend), garantindo que os alertas de emprego cheguem na caixa de entrada e não caiam no Spam.

Proteção JWT: O link de descadastramento (Unsubscribe) inserido no rodapé do e-mail é assinado com JSON Web Tokens para evitar manipulação ou exclusão acidental por bots.

Painel de Gestão e Auditoria (Admin)

Os administradores têm acesso a uma interface restrita através da rota /admin/subscribers.

  • Segurança: Acesso isolado através de Basic Authentication. Nenhum dado é exposto sem as credenciais do sistema.
  • Soft Delete: A técnica de exclusão em banco foi adaptada para manter o histórico. Quando o usuário clica em descadastrar, ele se torna "Inativo", permitindo relatórios reais.
  • Extração de Dados: Há uma rota programática (/admin/subscribers/export) para download instantâneo de toda a tabela em formato CSV, integrando-se rapidamente com Excel/BI.
📄 API / Endpoints / Vagas e Motor

Vagas e Motor (Render)

O Frontend na Vercel se comunica de forma transparente com o Backend no Render (via proxy transparente no vercel.json).

GET /api/vagas

Retorna a lista de vagas consolidadas no arquivo temporário JSON. Usado pelo Grid Principal.

POST /api/analyze

Realiza o cálculo de TF-IDF entre o CV (PDF/LinkedIn) e a base de vagas, retornando um objeto com as porcentagens de similaridade.

POST /api/refresh

Força a execução assíncrona do motor do Scraper, respondendo status HTTP 202 (Accepted) ou 429 se já estiver rodando.

📄 API / Endpoints / Autenticação

Autenticação de Usuários

Todas as interações salvam os dados no Supabase (PostgreSQL).

POST /api/auth/register

Cria uma nova conta de usuário, retornando 201 e um token JWT inicial.

POST /api/auth/login

Autentica o usuário validando as hashes criptografadas no Supabase e gerando um Bearer Token.

POST /api/user/profile

Endpoint protegido (Requer JWT) que aceita Multipart/Form-Data para gravar o PDF e a URL do LinkedIn no perfil do usuário no banco em nuvem.

📄 API / Endpoints / Newsletter

Inscrições de Newsletter

POST /api/newsletter

Grava um novo assinante com suas categorias e frequências diretamente no Supabase. É equipado com verificações anti-spam básicas e limites (Rate Limit).

GET /api/newsletter/unsubscribe

Rota engatilhada pelos links nos e-mails. Valida o Token JWT do e-mail e aplica Soft Delete no Supabase (status = false).

📄 API / Endpoints / Admin

Endpoints Administrativos

Todas estas rotas exigem HTTP Basic Auth via cabeçalho. As credenciais padrões devem ser configuradas nas variáveis de ambiente do Render.

GET /admin/subscribers

Retorna um Painel HTML renderizado no servidor com a lista paginada de todos os inscritos (Supabase).

GET /admin/subscribers/export

Gera dinamicamente um arquivo CSV contendo os dados brutos, incluindo inativos e timestamps.
