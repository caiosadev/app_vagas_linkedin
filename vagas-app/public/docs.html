Visão Geral do Projeto

Bem-vindo à documentação oficial do Vagas e Oportunidades. Este projeto foi concebido para atuar como um ecossistema completo e automatizado de extração, análise e notificação de vagas de emprego.

Status: Produção ativa. O sistema realiza scrapings horários e possui interface consumidora em React (Vite).

Objetivos de Negócio

  • Garantir ao candidato acesso rápido a oportunidades sem depender exclusivamente das notificações falhas das redes profissionais.
  • Filtrar vagas de altíssima concorrência.
  • Prover uma análise de aderência (Match Score) usando Inteligência Artificial (NLP).

Tecnologias Principais

Camada Tecnologia Propósito
Frontend React (Vite) Interface de usuário responsiva e moderna (Glassmorphism).
Backend Python (Flask) API RESTful, rotinas de background e endpoints do sistema.
Banco de Dados SQLite Armazenamento leve e local (users.db, newsletter.db).
Automação APScheduler Agendamento de extrações e disparos de e-mail automatizados.

Arquitetura do Sistema

O fluxo de dados da aplicação é desenhado para ser resiliente e assíncrono. O Frontend React atua apenas como consumidor dos dados que o Backend gera de forma autônoma.

Diagrama Lógico

[LinkedIn API/Scraper] ----(Extrai a cada 1h)---> [ JSON Local (.tmp) ]
                                                        |
[Currículo PDF] ---(PyMuPDF / OCR)--> [TF-IDF Match] ---+---> [ Frontend React ]
                                                        |
[Newsletter Jobs] <-------(Cron Múltiplo)---------------+

Instalação & Setup Local

Siga os passos abaixo para rodar o projeto em sua máquina local para desenvolvimento.

1. Backend (Python)

Recomendamos o uso de um ambiente virtual (venv).

cd execution
python3 -m venv venv
source venv/bin/activate
pip install flask pyjwt linkedin-api apscheduler pymupdf scikit-learn pdf2image pytesseract
python server.py

O servidor iniciará na porta 5001.

2. Frontend (React)

cd vagas-app
npm install
npm run dev

O Vite subirá na porta 5173, e os proxies no vite.config.js farão o roteamento das chamadas /api/* para a porta 5001 do Python.

📄 Docs / Core Engine / Scraper (LinkedIn)

Motor de Scraper

O linkedin_scraper.py é o coração da aquisição de dados. Ele utiliza a biblioteca não-oficial linkedin-api para buscar oportunidades.

Estratégia de Dupla Fonte

O script varre duas fontes simultaneamente para cada termo-chave:

  1. Seção de Vagas: Busca as oportunidades formais postadas por empresas.
  2. Feed / Timeline: Busca posts de recrutadores. O frontend consolida essas buscas se o titulo_vaga for "Vaga via Post" garantindo o termo_busca correspondente.

Regras de Ordenação

As vagas extraídas são ordenadas pela concorrência antes de serem salvas:

vagas_encontradas.sort(key=lambda x: (
    x["concorrencia"]["comentarios"], 
    x["concorrencia"]["compartilhamentos"]
))

Isso garante que o painel exiba primeiro oportunidades menos saturadas.

📄 Docs / Core Engine / Match de Currículo

Sistema de Matching (TF-IDF)

Para fornecer o "Score de Afinidade" aos candidatos, implementamos uma análise vetorial via Scikit-Learn no arquivo server.py (rota /api/analyze).

Fluxo de Leitura

1. O usuário anexa um PDF.

2. O PyMuPDF (fitz) tenta ler o texto puro.

3. Se a extração resultar em menos de 50 caracteres (indicando um PDF de imagem), o sistema invoca o pytesseract (OCR) para forçar a extração ótica.

Cálculo TF-IDF

vectorizer = TfidfVectorizer(stop_words=stopwords_pt)
tfidf_matrix = vectorizer.fit_transform([texto_curriculo, texto_vaga])
similaridade = cosine_similarity(tfidf_matrix[0:1], tfidf_matrix[1:2])
score = round(similaridade[0][0] * 100)

Se o score for maior que 85%, o sistema o classifica na interface com cores de destaque.

📄 Docs / Core Engine / Newsletter System

Disparo de Newsletters

A funcionalidade de e-mails é controlada pela tabela subscribers no banco de dados newsletter.db.

Frequências de Disparo

  • 1x ao dia: E-mail consolidado matinal.
  • 3x ao dia: Manhã, Tarde e Noite.
  • 5x ao dia: A cada poucas horas durante horário comercial.

Template HTML Dinâmico

O server.py lê o arquivo `vagas_extraidas.json`, cruza as "areas" que o usuário se inscreveu, renderiza uma tabela HTML responsiva e despacha via SMTP do Gmail. O link de unsubscribe utiliza um token JWT seguro.
